# 09 MEMORY_ARCHITECTURE (Truth-Mode Update)   
- **DDR3L (Tier 2)**: Arty A7‑100T has 256 MB of DDR3L on a 16‑bit bus at 333 MHz (667 MT/s).  This yields ~1.334 GB/s of *peak sequential* bandwidth.  **Critically**, graph queries are *random-access* heavy: each DRAM row activation can incur tens to hundreds of nanoseconds of latency.  Thus, Tier 2 is bulk storage for the full knowledge graph, **not** a streaming channel.  We treat DDR as the canonical backing store.  
- **On-chip Memory (Tier 1)**: Only a small subset of DDR data can be cached in BRAM/LUTRAM.  We allocate a **semantic cache in BRAM** to hold the “active frontier” (hot node IDs, role bindings, and hot relations).  For example, if node A and node B are currently active (in the query/workset), their immediate neighbors or frequently accessed neighbors are promoted into BRAM.  This yields *low‑latency* access for the most likely next-hop lookups.  ARM­-style LRU/LFU policies or a hardware profiler track “hot” nodes and edges to admit and evict from BRAM.  (Importantly, promotion is a copy of data – the DDR copy remains the truth.)  
- **Bandwidth vs. Latency**: The 1.33 GB/s number is *theoretical peak* for linear bursts.  In practice, **DDR latency dominates**.  For each random edge lookup, 50–100 ns may pass before data returns.  Without caching, a multi-hop search would stall awaiting DRAM on every hop.  Our architecture **relies on Tier 1 caching** to amortize DRAM latency.  (See [Prior Art](#02_PRIOR_ART_AND_NOVELTY) on multi-level cache for graph workloads.)  

# 10 ACTIVATION_AND_ROUTING (Truth-Mode Update)   
- **Spreading Activation**: We implement the classic **spreading-activation** mechanism on hardware.  The query’s subject/context nodes are first loaded into the active frontier (BRAM).  Those nodes broadcast pulses along their outgoing edges.  The *Graph Walker* reads those edges from DDR but only for *active* source nodes in BRAM.  (This matches the EPFL MOMS approach: if a source node is in the active set, its value is fetched from local BRAM, not DRAM.)  
- **Edge Intersection**: Edges from different active sources are compared to find *common destinations*.  Concretely, as each DRAM edge (src→dst) is fetched, its `dst` ID is checked via a LUT-based comparator against a hashtable or other edge index to see if multiple active sources lead to the same `dst`.  This hardware comparator detects in *one clock* if “A→Z” and “B→Z” coincide.  Matching destinations are scored as answer candidates.  This implements the “giao nhau ở một điểm” (intersection) logic mentioned in discussion.  
- **Event Routing**: Activation pulses (events) carry semantic IDs and context through a packet network.  Our protocol ensures ordering and CRC for reliability.  Pulses expire if no matching destination is found in a bounded time, implementing **time-to-live** semantics for activation.  

# 11 WORKING_MEMORY (Truth-Mode Update)   
- **Role Bindings & Frontier**: The working memory holds the **current query frame**.  For example, for a query “Who uses refrigerant?”, Subject=AIR_COND, Relation=USES_REFRIGERANT, Object=? – AIR_COND (subject) is bound in a BRAM slot.  This binding remains static while the FPGA searches the graph.  The active frontier initially contains AIR_COND and perhaps other context nodes.  
- **Active Nodes in BRAM**: As the algorithm proceeds, nodes that become “active” (found as common neighbors) are written into BRAM as well.  BRAM thus holds all active nodes (“muscle memory”) at once.  All other nodes reside in DDR (Tier 2).  This ensures tight, few-clock access to the most relevant nodes.  
- **Trajectory**: Working memory also tracks a *frontier queue* or stack of nodes to visit next.  Each clock tick, one or more BRAM-held nodes drive DDR fetches of their neighbor lists, then deposit new hits back into the frontier if needed.  This implements a pipelined search/expansion frontier.  

# 02 PRIOR_ART_AND_NOVELTY (Clarification)   
- We explicitly build on the concept of caching active subgraphs from graph-acceleration literature.  For instance, Liu et al. (ISCA’21) describe an FPGA design where **active source nodes are cached in BRAM to accelerate graph traversal**.  Our architecture applies this idea to semantic queries: BRAM stores the “source active set” for quick edge expansion.  
- This organization differs from traditional neural memory: we keep **persistent semantic objects in memory** and only activate them sparsely (via pulses).  It also differs from pure neuromorphic weight matrices, since knowledge is explicit.  (See [Hypothesis](#01_RESEARCH_HYPOTHESIS) for the full rationale.)
